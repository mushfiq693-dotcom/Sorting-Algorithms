1. ISSUE DESCRIPTION & THREAT MODEL (BEFORE FIX)
================================================================================

Previous Vulnerability:
  The application was deployed without standard HTTP defense-in-depth response
  headers and lacked a Content-Security-Policy (CSP).

Threat Vectors:
  1. Clickjacking: Without `X-Frame-Options: DENY` / `frame-ancestors 'none'`,
     malicious sites could embed AlgoHub inside invisible iframes to hijack user clicks.
  2. MIME-Type Sniffing: Without `X-Content-Type-Options: nosniff`, browsers could
     execute non-executable files as scripts if MIME types were misidentified.
  3. Referrer Leaks: Without `Referrer-Policy: strict-origin-when-cross-origin`,
     full URLs could leak to external destinations.
  4. Unrestricted Hardware APIs: Without `Permissions-Policy`, browsers did not
     explicitly disable camera, microphone, or geolocation APIs.
  5. XSS & Code Injection: Without a tailored CSP, the app lacked browser-enforced
     boundaries on script, style, image, font, and worker sources.

The following 7 HTTP security response headers are now configured in `next.config.ts`
for all routes (`/:path*`):

     font-src 'self' data:; connect-src 'self'; worker-src 'self' blob:;
     frame-ancestors 'none'; object-src 'none'; base-uri 'self'; form-action 'self';

2. X-Content-Type-Options
   Value: "nosniff"

3. X-Frame-Options
   Value: "DENY"

4. Referrer-Policy
   Value: "strict-origin-when-cross-origin"

5. Permissions-Policy
   Value: "camera=(), microphone=(), geolocation=(), browsing-topics=()"

6. Strict-Transport-Security (HSTS)
   Value: "max-age=63072000; includeSubDomains; preload"

7. X-DNS-Prefetch-Control
   Value: "on"

3. RATIONALE FOR EACH HEADER & CSP DIRECTIVE
================================================================================

Directive / Header                      Selected Rationale & Compatibility
--------------------------------------------------------------------------------
default-src 'self'                      Restricts all default resources to same origin.
script-src 'self' 'unsafe-inline' ...   Permits Next.js bundles, inline chunks, and Web Worker execution.
style-src 'self' 'unsafe-inline'        Permits Tailwind CSS and dynamic inline bar heights in Framer Motion.
img-src 'self' blob: data:              Permits SVGs, Canvas Confetti particle canvases, and Blob images.
font-src 'self' data:                   Permits self-hosted Google Fonts (Outfit, JetBrains Mono) via next/font.
connect-src 'self'                      Restricts all fetch/XHR network requests to the same origin.
worker-src 'self' blob:                 CRITICAL: Explicitly permits the Coding Practice Web Worker sandbox (Blob URL).
frame-ancestors 'none'                  Modern CSP equivalent of X-Frame-Options: DENY (blocks iframe embedding).
object-src 'none'                       Completely disables legacy Flash, Java, and Silverlight plugin vectors.
base-uri 'self'                         Prevents malicious manipulation of HTML <base> tag.
form-action 'self'                      Prevents form submission redirection attacks.
X-Content-Type-Options: nosniff         Prevents browser MIME-type sniffing.
X-Frame-Options: DENY                   Legacy & modern clickjacking defense for older clients.
Referrer-Policy: strict-origin...       Protects user privacy by stripping paths on cross-origin requests.
Permissions-Policy: camera=(), ...      Disables unused sensitive browser device APIs.
Strict-Transport-Security (HSTS)        Enforces HTTPS across all subdomains with 2-year cache + preload.
X-DNS-Prefetch-Control: on              Enables safe DNS prefetching for performance.

4. WEB WORKER & CSP COMPATIBILITY EXPLANATION
================================================================================

Why `worker-src 'self' blob:` and `script-src ... 'unsafe-eval'` were required:
  1. The Coding Practice sandbox (`src/lib/codeWorkerRunner.ts`) instantiates Web
     Workers dynamically via inline Blob URLs (`URL.createObjectURL(blob)`).
     Without `worker-src 'self' blob:`, modern browsers strictly block inline
     worker creation with a Content Security Policy violation.
  2. Inside the isolated Web Worker thread, user-submitted code is evaluated via
     `new Function(wrappedCode)`. The `'unsafe-eval'` directive inside `script-src`
     allows this evaluation within the worker context while keeping it safely
     isolated from DOM/storage on a background thread with 1000ms timeout protection.
