1. ISSUE DESCRIPTION & ARCHITECTURAL NEED (BEFORE FIX)
================================================================================

Previous State:
  The Next.js App Router tree lacked custom error boundaries (`error.tsx`, `global-error.tsx`).

Risk Vectors:
  1. Framework Error Leakage: In the event of an unhandled runtime error in a component
     or route, users would see an unbranded framework crash screen or blank page.
  2. Information Disclosure: Raw stack traces, system paths, or environment identifiers
     could accidentally be exposed to client-side users.
  3. Trapped User Experience: Users had no direct way to reset the component state
     or safely navigate back to the home learning journey.

================================================================================
2. IMPLEMENTED ERROR BOUNDARY ARCHITECTURE
================================================================================

We implemented a 2-tier error handling architecture adhering to Next.js App Router conventions:

1. Route-Level Error Boundary (`src/app/error.tsx`):
   - Scope: Catches runtime errors occurring anywhere inside page components, visualizers,
     or client components across all routes (`/`, `/learn`, `/algorithms/*`, `/compare`, `/docs`).
   - Props: `{ error: Error & { digest?: string }; reset: () => void }`.
   - Behavior:
     * Keeps root layout and navigation intact.
     * Renders an accessible, glassmorphic recovery card.
     * Safe developer telemetry: logs error message via console.error without exposing traces to DOM.
     * Offers two intuitive actions:
       - Primary: "Try Again" (invokes Next.js `reset()` to re-render segment).
       - Secondary: "Back to AlgoHub" (links to `/`).

2. Root Global Error Boundary (`src/app/global-error.tsx`):
   - Scope: Catch-all boundary in the rare event that the root `layout.tsx` itself crashes.
   - Behavior: Renders custom `<html>` and `<body>` tags with standalone dark theme styles.

3. USER-FACING COPY & ACCESSIBILITY
================================================================================

Heading:
  "Something went wrong."

Supporting Copy:
  "AlgoHub encountered an unexpected error. You can try again or return to the learning experience."

Actions:
  - "Try Again" (Primary red-gradient action button)
  - "Back to AlgoHub" (Secondary dark glass button)

Accessibility & Security Safeguards:
  - Semantic Heading: `<h1 className="...">Something went wrong.</h1>`
  - ARIA Live Region: `role="alert"` and `aria-live="assertive"` for screen readers.
  - Visible Focus States: `focus-visible:ring-2 focus-visible:ring-rose-400`.
  - Zero Sensitive Leaks: Zero stack traces, file paths, or internal IDs rendered in UI.
  - Safe Next.js Digest: If `error.digest` is provided, renders a clean hash identifier.
  - Reduced Motion: Fully compatible with `prefers-reduced-motion`.
