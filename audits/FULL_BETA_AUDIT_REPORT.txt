1. EXECUTIVE SUMMARY
================================================================================
AlgoHub has evolved into a robust, high-performance, and pedagogically rich
algorithm learning platform. The application is built on Next.js 15 (App Router)
with TypeScript, Tailwind CSS, and Supabase (PostgreSQL + Auth + Row Level Security).

Current System Health:
- Core Visualizer & Pedagogy: Complete interactive sorting visualizer supporting
  5 algorithms (Bubble, Selection, Insertion, Merge, Quick Sort) with step-by-step
  playback, SVG architectural diagrams, mathematical time/space derivations, code
  inspection in 4 languages (C++, Python, Java, TypeScript), and interactive practice
  modules (Bug Hunt, Predict Next Step, Multiple Choice Quizzes, and a dedicated
  Web Worker Coding Sandbox).
- Courseware & Theory: 17 in-depth documentation and tutorial articles with dual
  English and bilingual (Bangla) conceptual notes, time complexity growth charts,
  and interactive calculators.
- Security & RBAC: Multi-layered defense-in-depth security model consisting of
  Next.js Edge Middleware route guards, client-side auth state listeners, and 100%
  Row Level Security (RLS) enforcement on all 5 PostgreSQL tables.
- Admin Moderation: Fully functional /admin/moderation dashboard allowing
  departmental administrators to review beta registrations, filter applicants,
  approve/reject/suspend students with 1-click status updates, inspect student
  feedback, and triage algorithm bug diagnostic reports.
- Automated Verification: 100% test pass rate across Web Worker sandbox isolation
  (5/5), algorithm correctness suites (30/30), adversarial PostgreSQL security
  checks (10/10), and clean Next.js production compilation (13/13 routes).

AlgoHub is structurally ready for a controlled departmental beta deployment.

4. AUTHENTICATION & AUTHORIZATION AUDIT
================================================================================

Auth Flow Summary:
1. Sign-Up:
   - Validates email structure and blocks disposable domains (tempmail, mailinator, etc.).
   - Detects domain typos (@gamil.com -> suggests @gmail.com).
   - Invokes supabase.auth.signUp() with metadata (full_name, department, student_id).
   - Trigger handle_new_user() creates profiles (role='student'), beta_access (status='pending'),
     and user_progress (completed_steps='[]').
   - Displays real email confirmation screen.
2. Session Persistence & Token Rotation:
   - Next.js Edge Middleware intercepts incoming requests to refresh tokens via createServerClient.
   - Uses supabase.auth.getUser() (server authenticated) rather than spoofable getSession().
3. Role & Status Gatekeeping:
   - Anonymous -> Redirected to /auth/login?next=... for protected paths.
   - Pending   -> Redirected to /auth/pending.
   - Rejected  -> Redirected to /auth/rejected.
   - Suspended -> Redirected to /auth/suspended.
   - Approved  -> Full access to all learning engines.
   - Admin     -> Exclusive access to /admin/moderation. Non-admins bounced to /.

Adversarial Testing & Spoofing Resistance:
- Role Escalation: Authenticated student attempting 'UPDATE profiles SET role = admin'
  is rejected by PostgreSQL RLS WITH CHECK policy.
- Status Escalation: Authenticated student attempting 'UPDATE beta_access SET status = approved'
  is rejected with 0 rows updated by beta_access_update_admin_only.

5. DATABASE & SUPABASE AUDIT
================================================================================

Schema Structure:
auth.users
  |-- (1:1 ON DELETE CASCADE) --> public.profiles
                                    |-- (1:1 ON DELETE CASCADE) --> public.beta_access
                                    |-- (1:1 ON DELETE CASCADE) --> public.user_progress
                                    |-- (1:N ON DELETE CASCADE) --> public.feedback
                                    |-- (1:N ON DELETE CASCADE) --> public.bug_reports

Table Specifications:
1. public.profiles:
   - PK: id (UUID -> auth.users)
   - Columns: email (TEXT, UNIQUE), full_name, department, student_id, role ('student'|'faculty'|'admin')
   - RLS: SELECT own or admin; UPDATE own (excluding role) or admin.
2. public.beta_access:
   - PK: id (UUID)
   - FK: user_id (UUID -> profiles), approved_by (UUID -> profiles)
   - Columns: status ('pending'|'approved'|'rejected'|'suspended'), approved_at, notes
   - RLS: SELECT own or admin; UPDATE admin only.
3. public.user_progress:
   - PK: id (UUID)
   - FK: user_id (UUID -> profiles)
   - Columns: completed_steps (JSONB), completed_docs (JSONB), quiz_scores (JSONB), last_active_at
   - RLS: ALL operations isolated to auth.uid() = user_id.
4. public.feedback:
   - PK: id (UUID)
   - FK: user_id (UUID -> profiles)
   - Columns: category, rating (1-5), message, page_url, created_at
   - RLS: INSERT own; SELECT own or admin.
5. public.bug_reports:
   - PK: id (UUID)
   - FK: user_id (UUID -> profiles)
   - Columns: algorithm_id, page_url, steps_to_reproduce, expected_behavior, actual_behavior, status
   - RLS: INSERT own; SELECT own or admin; UPDATE admin only.
