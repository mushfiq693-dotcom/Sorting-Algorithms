1. EXECUTIVE SUMMARY & BACKEND GOALS
================================================================================
The AlgoHub backend is engineered as a secure, production-grade, departmental
beta infrastructure. It enforces strict role-based access control (RBAC),
protects proprietary learning modules from unauthorized or anonymous access,
and ensures that only verified students and faculty approved by the departmental
administrator can use the interactive engines.

Key Objectives Accomplished:
- 100% cloud PostgreSQL database schema with automated migrations and rollbacks.
- Strict Row Level Security (RLS) across all 5 database tables (13 policies).
- Multi-tier route security via Next.js Edge Middleware.
- Automatic genuine email verification and disposable/fake email blocker.
- Seamless dual-telemetry sync (local browser state <-> cloud database).
- Complete Admin Moderation Dashboard with live queue management.
- Zero reliance on external mailto links (integrated with Google Forms).

2. DATABASE ARCHITECTURE & TABLES (PostgreSQL)
================================================================================
All database definitions are modularized under `backend/database/`.

[Table 1] public.profiles
- Purpose: Stores student and faculty academic profile information.
- Columns:
  * id (UUID, PK) -> REFERENCES auth.users(id) ON DELETE CASCADE
  * email (TEXT, UNIQUE, NOT NULL)
  * full_name (TEXT)
  * department (TEXT, DEFAULT 'CSE')
  * student_id (TEXT, e.g. '24CSE031')
  * role (TEXT, DEFAULT 'student', CHECK: 'student' | 'faculty' | 'admin')
  * created_at (TIMESTAMPTZ, DEFAULT now())
  * updated_at (TIMESTAMPTZ, DEFAULT now())

[Table 2] public.beta_access
- Purpose: Controls platform unlock permissions and departmental approval status.
- Columns:
  * id (UUID, PK, DEFAULT gen_random_uuid())
  * user_id (UUID, UNIQUE, NOT NULL) -> REFERENCES public.profiles(id) ON DELETE CASCADE
  * status (TEXT, DEFAULT 'pending', CHECK: 'pending' | 'approved' | 'rejected' | 'suspended')
  * approved_by (UUID) -> REFERENCES public.profiles(id) ON DELETE SET NULL
  * approved_at (TIMESTAMPTZ)
  * notes (TEXT)
  * created_at (TIMESTAMPTZ, DEFAULT now())
  * updated_at (TIMESTAMPTZ, DEFAULT now())

[Table 3] public.user_progress
- Purpose: Tracks student curriculum progress, quiz scores, and telemetry.
- Columns:
  * id (UUID, PK, DEFAULT gen_random_uuid())
  * user_id (UUID, UNIQUE, NOT NULL) -> REFERENCES public.profiles(id) ON DELETE CASCADE
  * completed_steps (JSONB, DEFAULT '[]')
  * completed_docs (JSONB, DEFAULT '[]')
  * quiz_scores (JSONB, DEFAULT '{}')
  * last_active_at (TIMESTAMPTZ, DEFAULT now())

[Table 4] public.feedback
- Purpose: In-app evaluations, ratings, and feedback submissions.
- Columns:
  * id (UUID, PK, DEFAULT gen_random_uuid())
  * user_id (UUID, NOT NULL) -> REFERENCES public.profiles(id) ON DELETE CASCADE
  * category (TEXT, NOT NULL)
  * rating (SMALLINT, CHECK: 1 <= rating <= 5)
  * message (TEXT, NOT NULL)
  * page_url (TEXT)
  * created_at (TIMESTAMPTZ, DEFAULT now())

[Table 5] public.bug_reports
- Purpose: Diagnostic logs for algorithm engine bugs or platform issues.
- Columns:
  * id (UUID, PK, DEFAULT gen_random_uuid())
  * user_id (UUID, NOT NULL) -> REFERENCES public.profiles(id) ON DELETE CASCADE
  * algorithm_id (TEXT)
  * page_url (TEXT, NOT NULL)
  * steps_to_reproduce (TEXT, NOT NULL)
  * expected_behavior (TEXT)
  * actual_behavior (TEXT)
  * browser_info (TEXT)
  * status (TEXT, DEFAULT 'open', CHECK: 'open' | 'investigating' | 'resolved' | 'closed')
  * created_at (TIMESTAMPTZ, DEFAULT now())
  * updated_at (TIMESTAMPTZ, DEFAULT now())

3. ROW LEVEL SECURITY (RLS) & ACCESS CONTROL
================================================================================
Row Level Security is enabled on 100% of tables. No user can read or write
unauthorized data directly from the client.

Security Rules Enforced:
1. `profiles`:
   - SELECT: Users can read their own profile; Admins can read all profiles.
   - UPDATE: Users can update full_name/student_id but CANNOT escalate their own role.
   - UPDATE (Admin): Admins can update any user's role and details.
2. `beta_access`:
   - SELECT: Users can read their own status; Admins can read all queue requests.
   - UPDATE: ONLY Admins can change status (Approve / Reject / Suspend).
3. `user_progress`:
   - SELECT / INSERT / UPDATE: Strictly isolated to the authenticated user owning the progress.
4. `feedback` & `bug_reports`:
   - INSERT: Any authenticated user can submit feedback or log bugs.
   - SELECT: Users can see their own submissions; Admins can view all submissions.

4. DATABASE TRIGGERS & AUTOMATION
================================================================================
1. Automated User Initialization Trigger (`handle_new_user()`):
   - Triggered: `AFTER INSERT ON auth.users`
   - Actions:
     * Extracts full_name, department, and student_id from signup metadata.
     * Automatically creates row in `public.profiles` (defaults to `role = 'student'`).
     * Automatically creates row in `public.beta_access` (defaults to `status = 'pending'`).
     * Initializes empty state in `public.user_progress`.
2. Timestamp Automation Trigger (`trigger_profiles_updated_at`, etc.):
   - Automatically updates `updated_at = now()` whenever a record is modified.

6. EDGE MIDDLEWARE & ROUTE GATEKEEPING
================================================================================
File: `src/middleware.ts` & `src/lib/supabase/middleware.ts`

Access Logic:
- Public Routes (Allowed for everyone):
  * `/` (Landing Page & Hero Section)
  * `/auth/login` (Auth Portal)
  * Static assets, images, favicons.
- Protected Routes (Requires Login + Beta Approval):
  * `/learn` (Interactive Curriculum & Sandbox)
  * `/algorithms/*` (Interactive Visualizers)
  * `/compare` (Multi-Algorithm Benchmark Engine)
  * `/docs/*` (Documentation & Learning Guides)
- Status-Based Redirects:
  * Not logged in -> `/auth/login?next=...`
  * Logged in & status == 'pending' -> `/auth/pending`
  * Logged in & status == 'rejected' -> `/auth/rejected`
  * Logged in & status == 'suspended' -> `/auth/suspended`
  * Logged in & status == 'approved' -> Allowed access.
- Admin-Only Route (`/admin/moderation`):
  * If `role !== 'admin'`, immediately redirected to `/` with access denied.

7. EMAIL VALIDATION & VERIFICATION SYSTEM
================================================================================
File: `src/lib/validation/emailValidator.ts`

Protection Features:
1. RFC Email Structure Regex Validation.
2. Disposable Domain Blacklist:
   - Blocks temporary email services (`tempmail.com`, `mailinator.com`, `10minutemail.com`, etc.).
3. Common Domain Typo Detection:
   - Catches typos like `@gamil.com`, `@gmial.com`, `@yaho.com` and provides smart suggestions.
4. Genuine Email Confirmation:
   - On signup, Supabase sends a secure confirmation link to the student's real inbox.
   - Clicking the email link confirms the identity and forwards to `/auth/pending`.
